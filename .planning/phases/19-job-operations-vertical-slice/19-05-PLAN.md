<objective>
Switch the production worker to the Job runner (ORCH-05) and make it boot with BACKTEST-level config, validating each Job type's declared ExecutionMode immediately before dispatch (D-22). A failing mode check lands the Job FAILED/`config_invalid` and the worker keeps running.

Design choice (Claude's discretion, resolved): injected preflight callable. `jobs/runner.py` gains an optional `preflight: Callable[[JobHandler], str | None]` parameter on `execute_job` and `run_worker_loop`; it imports nothing from `services`. `worker/commands/run_jobs.py` supplies `required_mode_preflight`, which reads the handler's `required_execution_mode` and calls the new pure helper `services.config.validation.config_failure_message`. The FAILED transition lives in `runner.py` because `test_run_jobs_is_a_thin_worker_loop_adapter` forbids transition code in `run_jobs.py`.
Output: runner hook, worker wiring, validation helper, compose switch, tests.
</objective>
