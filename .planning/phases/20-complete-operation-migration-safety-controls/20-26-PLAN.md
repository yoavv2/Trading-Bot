<objective>
Close UAT gap 3. A re-opened control or job confirmation dialog renders the previous opening's state on its first committed frame. That includes a stale role=alert, an old reason with confirm enabled, or the "Already X" notice. After unchanged -> Close -> re-open, focus sticks on "Keep Current State" instead of the reason field.

The cause is reset-in-a-passive-effect on a dialog that stays mounted. The fix, per locked user decision 3:
- each dialog becomes a persistent outer shell plus a per-opening body that mounts fresh on every opening, and the reset effect is deleted;
- ControlConfirmDialog's shell keeps openingRef/wasOpenRef so the WR-C-01 guard survives;
- the outer dialog is never keyed, because keying it would reset openingRef and regress WR-C-01.

Purpose: every opening is clean from its first frame, so a screen reader never announces a stale alert and an operator never confirms with a stale reason.
Output: three refactored dialogs, first-frame and focus regression tests, and the 20-UI-SPEC and WR-C-05 amendments.

Coordination: this plan touches only console/src files listed above plus two phase docs. It must not modify or stage console/README.md, which holds uncommitted user work, or any other user-modified file (Makefile, README.md, docker-compose.yml, tests/test_orchestration_boundaries.py, tests/test_dev_workflow.py). Stage by explicit path only.
</objective>
