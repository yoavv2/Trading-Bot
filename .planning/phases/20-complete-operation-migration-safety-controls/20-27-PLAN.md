<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Alpaca paper REST API -> AlpacaClient | Untrusted remote payloads (page contents, ids) drive the pagination loop |
| AlpacaClient -> reconciliation/sync matchers | Incomplete broker sets produce wrong safety findings (fail-open for fills, false blocking for orders) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-27-01 | Denial of service (unbounded loop / memory) | _paginate | mitigate | Hard caps ALPACA_FILLS_MAX_PAGES=100 and ALPACA_ORDERS_MAX_PAGES=20 (at most 10,000 items per call). Exceeding a cap raises AlpacaPaginationCapExceededError (test_list_fills_cap_raises, test_list_orders_cap_raises) |
| T-20-27-02 | Tampering / integrity (silent truncation) | list_fills / list_orders | mitigate | Cursor pagination until a short page, and never a partial return. Stall detection on duplicate ids, a non-advancing cursor, a missing id or a non-list payload. The cursor key is absent (never empty) on request 1 |
| T-20-27-03 | Denial of service (infinite loop from a server echoing the cursor) | _paginate | mitigate | Duplicate-id and cursor-did-not-advance checks raise AlpacaPaginationStalledError on the first repeat |
| T-20-27-04 | Information disclosure | pagination error messages | mitigate | Messages carry endpoint, cursor id and counts only, never headers or API keys |
| T-20-27-05 | Tampering (false MISSING_BROKER from asymmetric windows) | date bounding | mitigate | No date, after or until parameter is ever sent (asserted in tests), so the broker window equals the unbounded local window |
</threat_model>
