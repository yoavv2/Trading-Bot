# Phase 20.1 Plan 15: Sequential Submission, Permission Check, Fresh Price and Start-Mode Gates Summary

**A paper session is now a sequential, pausable operation: it creates the operation at the first submission (owner re-checked under the singleton lock, basis verified, replays and already-submitted actions listed and never sent), sends one intent at a time through the S1 send authorization, runs the fixed-precedence permission check (window, provenance, pauses, fresh latest-trade price, pinned-intent risk) before every order, pauses after every accepted order and every ambiguous or unavailable step with the unsent intents preserved, and a new or retried request is refused at submit time by the start-mode gates.**

**5. [Interpretation] Domain-conflict map:** the plan names `OperationConflictError` (lost CAS, open-operation race) and `RiskRunAlreadyOperatedError`. A refused T1 surfaces as `OperationConflictError("send_refused:<refusal>")`; an executor that loses authority AFTER a POST raises `ExecutionAuthorityLostAfterSendError`, deliberately NOT translated (the POST was sent).

**6. [Interpretation] Reported choices:**
- `JobContext` is frozen and carries no lease owner: the executor reads `Job.lease_owner` once at session start (this process certainly holds the lease then); every T1 re-verifies it. A Job-less service call cannot hold authority (`ExecutorJobRequiredError`); tests use the seam, production has no bypass.
- Operation creation is its own transaction (SER lock FOR SHARE + owner re-check) right after the paper_execution run's first-write row, not literally the same transaction (the run row must stay the LOCK-03 first write).
- Gate order: the new gates sit after the 20.1-10 recovery gate and before the manifest check, so an open operation or a working order is reported before a heavy manifest verification; ownership -> eligibility -> recovery -> operation gates -> manifest.
- `risk_run_id: null` is resolved by ONE predicate (parameters_snapshot as_of_session) at submit, in the manifest check and at run time (`_load_auto_resolve_candidates` / `_resolve_source_risk_run` no longer also accept `result_summary`), closing the 20.1-06 handoff.
- The S2-R3 observation is audited as an `ExecutionEvent` `intent_permission_checked` on the order's run (the attempt table has no details column); an unrecognized-count lookup applies to ACCOUNT-scope reconciliations only (strategy-scope runs report 0, so they read `reconciliation_blocking`).
- `prior_execution_refs` = the strategy's earlier orders on the same SYMBOL (any session or side): the plan's N2 requires a later-session exit to name the buy it closes.
- `revalidate_pinned_intent(pinned, portfolio_state, risk_config, price)` is pure (no session or strategy arguments); it never returns `order_rounds_to_zero` although `RISK_LIMIT_PORTFOLIO_CODES` (20.1-11) lists it.
- `test_partial_exit_remainder_per_strategy` drives each strategy's REAL `_evaluate_symbol` over scripted bars; the platform side of the test uses the fixture strategy (S3-R4 is strategy-agnostic).
