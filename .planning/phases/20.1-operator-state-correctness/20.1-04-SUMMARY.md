# Phase 20.1 Plan 04: Batch Outcomes and Symbol Readiness (COR-03) Summary

**Batch Jobs now read `complete | partial | failed` derived from the domain result (never a Job column), `sync-symbol-metadata` separates per-symbol failures from operation-level ones in a two-phase sync, and a symbol missing required metadata is `not_ready(missing_metadata)` and rejected by risk with the new closed code `symbol_not_ready`.**

## Accomplishments

- `services/batch_outcomes.py`: closed `BatchOutcome`, `SymbolFailureReason {not_found, missing_required_fields, invalid_response, fetch_error}`, `OperationFailureReason {provider_auth, invalid_configuration, database_write, provider_unavailable}`, `BATCH_OUTCOME_JOB_TYPES`, `outcome_from_ingestion_run_status` (ValueError on an unknown status), `derive_batch_outcome`, `derive_job_outcome`. No `jobs/` import.
- ingest-bars: result_summary gains `outcome` from the persisted run status; `raise_for_all_symbols_failed()` and the cancel ordering are unchanged (all-fail still raises, Job FAILED).
- Job reads: `list_jobs` items and `get_job_detail` gain an additive `outcome` (string or null). The `710d46bf` shape (SUCCEEDED, non-empty `symbols_failed`, no stored outcome) reads `partial`. `test_jobs_table_columns_are_unchanged` pins the exact 30-column set of `jobs`.
- `sync_symbol_metadata` rewritten: phase 1 (no DB writes) checks the API key, then fetches and classifies each ticker (404/None -> not_found; missing market/type/primary_exchange -> missing_required_fields; non-dict or unparseable payload -> invalid_response; transport/5xx/429/other HTTP error -> fetch_error). `PolygonAuthError` stops immediately (`provider_auth`); all tickers transiently failing is `provider_unavailable`; phase 2 upserts all valid overviews in ONE `session_scope` and any error there is `database_write` with everything rolled back. `MetadataSyncResult` gains `failures`, `operation_failure`, `outcome`; `skipped` is kept as an always-empty list; `raise_for_failures` is removed and replaced by `raise_if_failed()` (raises only for outcome `failed`). `fetch_ticker_overview` keeps its signature and now raises `InvalidOverviewResponseError` for a malformed body. Log lines carry exception class names and tickers only.
- Handler: logs completion, then `raise_if_failed()`, then the post-call cancel checkpoint; summary keeps all existing keys and adds `outcome`, `failures`, `operation_failure`. Partial leaves the Job SUCCEEDED; failed lands FAILED (`handler_error`).
- `services/symbol_readiness.py`: `symbols_readiness(session, tickers)` is one SELECT for any number of tickers (verified with `count_queries` for 1 and 50); ready iff metadata_provider set, active, market `stocks`, symbol_type in {CS, ETF}, non-blank primary_exchange; unknown ticker is not_ready with all five requirements missing.
- `RiskDecisionCode.SYMBOL_NOT_READY`: `PortfolioRiskService.validate` reads readiness once for the non-flat signal symbols; `_evaluate_signal` rejects a not-ready symbol right after the flat check and before the stale-data check (exits included). Other signals are decided as before. No migration (`alembic/versions` unchanged; head stays 0023).
