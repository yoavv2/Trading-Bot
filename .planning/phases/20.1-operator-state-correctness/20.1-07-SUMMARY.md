# Phase 20.1 Plan 07: Evidence-Based Attribution, Reconciliation Blocking and Adoption-Free Sync Summary

**Broker orders and fills are classified owned / recorded_external / unrecognized from local registration evidence (never from id shape), unexplained exposure, owned-order anomalies, unrecognized activity and page-cap overflow each block reconciliation, a prior owner's orders do not block the new owner, and broker sync no longer adopts positions (they derive from owned fills).**

## Accomplishments

- `classify_broker_activity` (pure): local match by client_order_id then broker_order_id; owned requires matching symbol/side/quantity (within QUANTITY_TOLERANCE)/order type, broker `created_at` not earlier than registration, and an own-strategy ownership period once periods exist. Fixed anomaly precedence attribute_mismatch > created_at (missing / before registration) > outside_ownership_period. No local match: recorded-external hook, else unrecognized with origin tag by precedence replaced_by_successor > status_unmapped > platform_format_unverified > external_format. A platform-format id with no local record is NEVER owned.
- Fills inherit class and owner through broker_order_id; a fill whose order is absent from the broker list is unrecognized. Unexplained exposure per symbol = broker signed quantity minus net owned/recorded-external fills; any non-zero value (and any unrecognized order, wherever it is in history) blocks.
- `reconcile_paper_execution`: classification over ALL strategies' intents (one joined statement), other-owner and recorded-external activity excluded from the strategy-scoped matcher, `blocks_execution = existing rule or attribution.blocks_execution`, additive `attribution` and `unresolved_reasons` in the run result_summary and `ReconciliationReport.to_dict()`.
- Page-cap overflow inside reconciliation is a SUCCEEDED, blocking, structured result (D-11); the in-session pre-load in `run_paper_session` is unchanged and stays fail-closed.
- `sync_paper_state` no longer creates positions from broker positions: `_sync_positions_from_broker` is deleted; `_derive_positions_from_owned_fills` derives weighted-average signed positions from the strategy's own PaperFills (two selects), closes open positions without supporting fills and never touches other strategies' fills.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Pure home for the broker status mapping**
- **Found during:** Task 1
- **Issue:** `classify_broker_status` / `BrokerStatusClass` lived in `services/alpaca.py`, which imports httpx at module level; the pure attribution module must not import it (plan: "import it lazily or via a pure module").
- **Fix:** moved the mapping, enum, `classify_broker_status` and `broker_status_reason` to `services/broker_status.py`; `services.alpaca` re-exports them (public names and the private `_BROKER_STATUS_CLASSES` alias). `tests/test_alpaca_submission_taxonomy.py` passes unchanged.
- **Files modified:** `services/broker_status.py` (new), `services/alpaca.py`
- **Commit:** cb8fd46

**2. [Rule 1 - Bug] Prior owner's broker position blocked the new owner**
- **Found during:** Task 2 design (the plan's own acceptance case: prior owner's orders must not block the new owner)
- **Issue:** excluding the prior owner's orders and fills from the matcher is not enough; the broker still reports their position and the matcher raised a blocking MISSING_LOCAL position finding for the new owner.
- **Fix:** `_matcher_scope` subtracts the net fills of the excluded orders from the matching broker positions (drops a position that nets to zero). No-op when nothing is excluded, so the single-owner path is byte-identical. Account divergence remains account-wide on the raw positions. Limitation: when a symbol is shared between owners the adjusted position keeps the blended broker average price.
- **Files modified:** `services/reconciliation/report.py`
- **Commit:** 2137cd1

**3. [Rule 3 - Blocking] Shared prefix normalization**
- **Issue:** the platform-format matcher needs the exact prefix-fragment normalization of `build_client_order_id`.
- **Fix:** extracted `client_order_id_prefix_fragment()` in `services/execution/idempotency.py` (not in the plan's file list); `build_client_order_id` now calls it; behaviour identical.
- **Commit:** cb8fd46

**4. [Process] Task 2 was not split into RED/GREEN commits**
- Tests and implementation for Task 2 were committed together (`2137cd1`) because the fixture updates it required had to land with the wiring.
