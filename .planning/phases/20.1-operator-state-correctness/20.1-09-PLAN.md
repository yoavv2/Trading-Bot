<objective>
Deliver EXT-01: the audited, minimal recovery path "Record external activity" (D-10, 03 §3.5, 05 M9). A Job re-fetches verified broker records for operator-listed unrecognized orders, requires them terminal and net-zero, stores immutable snapshots with a content hash and preserved origin (no strategy, no position), and in the same handler runs a fresh account-level reconciliation whose result is the Job outcome. Recording by itself never lifts a block; only that fresh result can, and every later check re-verifies the recorded items against the broker.

Purpose: an operator who did a manual trade in the paper account must be able to return the account to a state the platform explains, without adopting external positions into any strategy (D-08, no adoption; non-terminal or non-zero external activity must first be neutralised at the broker, TL-5).
Output: migration 0025 + immutable model; `services/external_activity.py`; hash-verified `recorded_external` classification wired into the 20.1-07 attribution and the 20.1-08 account reconciliation; the `latest_broker_effect_at` boundary; the `record-external-activity` Job type (spec, handler, registry, closed domain-conflict reasons); migration, service, spec/handler tests.

Design notes recorded here (implementation choices, not product decisions):
- Row grain: one row per recorded broker order (order snapshot + that order's fills as JSON). The latest row (created_at, then id) per broker_order_id is what checks compare; an older row never keeps an item explained once a newer divergent one exists.
- Immutability is enforced by the database (BEFORE UPDATE/DELETE trigger permitting only job_id NOT NULL -> NULL, which is what the FK's ON DELETE SET NULL performs), not only by convention.
- SPEC GAP resolved here (reported in the SUMMARY): 03 §3.3 A6 says "after the latest broker-touching Job and after any recording", but the recording Job runs its own fresh check inside itself, so Job.completed_at would always postdate it. The boundary therefore uses each type's effect time (rows' created_at for this type).
- `order_owned_by_strategy` is an addition to the three closed reasons of 03 §3.5 (a refusal reason of the Job: JobDomainConflictError, outcome_uncertain false, zero writes, the code as the first token of failure_message; not an HTTP 409 and not per-item), needed so that an owned order can never be recorded as external; it is recorded as a spec delta to 03 §3.5, 04 V14 and 05 M9 (20.1-CONTEXT amendments).
