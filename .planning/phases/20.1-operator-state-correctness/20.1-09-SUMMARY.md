# Phase 20.1 Plan 09: Record external activity Summary

**An audited Job re-fetches verified broker records for operator-listed external orders, requires them terminal and net-zero, stores immutable hash-verified snapshots with no strategy and no position, and runs a fresh account-level reconciliation in the same handler; every later check re-verifies the recorded items from the broker lists it already loaded.**

## Accomplishments

- Migration 0025 (`down_revision` 0024): `external_broker_activity` with no strategy column and no FK except `jobs` (`ON DELETE SET NULL`); closed `side` / `origin_tag` CHECKs, non-blank `reason`, 64-lowercase-hex `content_hash`, unique `(broker_order_id, content_hash)`; a trigger rejects every DELETE and every UPDATE except the FK null-out. Downgrade drops table, function and indexes. Linear chain, single head.
- `record_external_orders`: broker reads first (no session open), then one transaction. Closed refusals with zero writes: `broker_record_unavailable` (404, transport/lookup failure, pagination cap, id mismatch, fills not adding up), `order_owned_by_strategy`, `external_order_not_terminal` (replaced needs its terminal successor listed; unmapped status is not terminal), `external_exposure_nonzero` (per symbol, recorded plus to-be-recorded). Origin tag is preserved from the classification.
- Attribution: `classify_broker_activity` takes `recorded_external: Mapping[id, RecordedExternalItem]` and recomputes the hash from the current broker order and fills. Match -> `recorded_external`; mismatch -> `unrecognized` with the preserved origin tag and `recorded_snapshot_mismatch`; recorded id absent from broker orders -> blocking `recorded_external_missing`. The provider (`load_recorded_external`) is one `DISTINCT ON` statement and no broker call; both `reconcile_account` and `reconcile_paper_execution` use it. The 07/08 empty hook is deleted.
- `latest_broker_effect_at` (exported from `services.reconciliation`) and `record-external-activity` added to `BROKER_TOUCHING_JOB_TYPES` (reads_broker) and `STATE_CHANGING_BROKER_JOB_TYPES`.
- Job type `record-external-activity`: strict `{order_ids (1..50, each 1..64 chars), reason (1..500)}` payload with eight closed rejection values; queued-only, `broker_effect = reads_broker`, `required_execution_mode = PAPER`, no retry prerequisite, SER admission hook (ownership singleton FOR SHARE, no ownership check). The handler records, then runs `reconcile_account` with the same broker client; result_summary carries `outcome` (clean | blocking), recorded / already-recorded ids and `produced_run_ids == [run_id]`; the Job is SUCCEEDED for both outcomes. A refusal becomes FAILED / `domain_conflict`, `outcome_uncertain` false, reason as the first message token. No route added or changed; `tests/test_console_api_contract.py` not edited.

## Deviations from Plan

### Auto-fixed / judgment calls

**1. [Rule 1 - Spec bug] Handler event codes are not `external_`-prefixed**
- The plan names `external_activity_recording_started` / `external_activity_recorded` / `external_activity_rejected` but also requires "NOT `external_`-prefixed" and a handler_error that is not uncertain. `jobs/runner.py:91` marks a later handler error uncertain when ANY log event_code starts with `external_`. Used `record_external_activity_recording_started`, `record_external_activity_recorded`, `record_external_activity_rejected` (they still contain the plan's substrings). A production-path test (fresh check raises -> Job `handler_error`, `outcome_uncertain` false) pins the behaviour.

**2. [Judgment] Registry sort position**
- The plan says `record-external-activity` sorts "between paper-session and reconciliation"; alphabetically `reconciliation` < `record-external-activity` (`n` < `r`), so the pinned lists put it after `reconciliation` and before `risk-evaluation`.

**3. [Judgment] Pure `services/external_snapshot.py`; loader in `attribution_inputs`**
- `content_hash` and `RecordedExternalItem` live in a new pure module because `attribution.py` is declared pure (no ORM) and must recompute the hash; `external_activity.py` re-exports `content_hash`. `load_recorded_external` lives in `attribution_inputs.py` (where the replaced stub was) to avoid an `attribution_inputs <-> external_activity` import cycle, and is re-exported from `external_activity`.

**4. [Rule 2 - Missing critical] Typed `filled_avg_price` on `BrokerOrderSnapshot`**
- The verified snapshot hash needs the average fill price and the snapshot had no typed field (the 08 `filled_quantity` precedent). Optional, default None, never raises.

**5. [Rule 2 - Missing critical] Fills must add up to the filled quantity; per-batch advisory lock**
- A fill list that does not sum to the broker's `filled_qty` is `broker_record_unavailable`, never recorded. Preconditions and insert are serialized by a transaction advisory lock (a closed-reason addition is not needed: it reuses `broker_record_unavailable`).

**6. [Judgment] `recorded_external_missing` shape**
- Typed `AttributionResult.recorded_external_missing` (blocking; key present in `to_dict` only when non-empty) and a stored finding dict (`event_type: recorded_external_missing`, severity `error`, blocking) on the account run. Strategy-scope `reconcile_paper_execution` blocks through `attribution.blocks_execution` and records it in `result_summary.attribution`, but writes no ExecutionEvent for it (the finding-category enum is closed).

**7. [Judgment] Extra index and ruff noise**
- Added `ix_external_broker_activity_created_at` (backs `max(created_at)` in `latest_broker_effect_at`). `ruff format` re-wrapped one unrelated line in `services/alpaca.py`.

## Handoffs for later plans

- **20.1-10 / 20.1-12:** the recovery predicate and A6 must use `latest_broker_effect_at(session)` as the `completed_after` boundary of `latest_standalone_reconciliation` (for a recording it is the rows' `created_at`; the recording Job's own `completed_at` must NOT be used). `BROKER_TOUCHING_JOB_TYPES` now includes `record-external-activity` (A1 sees queued/running recordings through the shared admission lock).
- **20.1-12:** `load_ownership_periods` still loads only the current owner's period (07 handoff, unchanged here). A recorded external item can never be adopted: handover must not try to convert one.
- **Live-payload risk (UAT):** the content hash relies on `GET /v2/orders/{id}` and `GET /v2/orders` returning identical typed fields (client_order_id, status, qty, timestamps, filled_qty, filled_avg_price, replaces / replaced_by). It is untested against live Alpaca; if the two payloads ever differed on a typed field, a freshly recorded item would read as `recorded_snapshot_mismatch` on the first check (fail closed, visible, recordable again). Worth one live check during UAT.
- **Operational:** a record request needs the orders terminal and net-zero at the broker first (TL-5); the closed refusal reasons say which. `record-external-activity` runs a fresh account reconciliation, which needs a prior broker-observed snapshot for divergence checks (run an account sync first, 08 handoff).
- **`default_strategy_id` fallback:** still not removed (unowned since 07/08).
