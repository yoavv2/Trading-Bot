Tests: `test_stale_fence_terminate_changes_nothing`, `test_transition_to_terminated_moves_the_proven_unsent_intents`.

### Interpretations (reported)

- **Crash normalization.** The plan text says a crash-left `running` operation reads as paused/awaiting_reconciliation. This plan reports it through the pure `effective_state` (`takeover_pending`, next action `sync_reconcile_then_continue`) and persists a change only inside `acquire_execution` (epoch CAS; in-doubt intents -> UNKNOWN and paused/outcome_unresolved). Persisting paused/awaiting_reconciliation on a touch would have made the operation resumable without the S1 takeover, which the plan forbids.
- **"Pure" `effective_state`.** It takes a `Session` (read-only calendar and Job facts) rather than only `(op, now)`; list reads load the calendar window once and call `compute_effective_state`.
- **TTL.** `ttl_seconds` is a keyword argument (default 5) because the `send_authorization_ttl_seconds` setting belongs to 20.1-15.
- **Intent `registered_unsent` for End.** Cancelled/expired dispositions apply to planned, registered_unsent and not_sent intents ONLY when `proven_not_sent` also holds (a legacy order reused later is excluded).
