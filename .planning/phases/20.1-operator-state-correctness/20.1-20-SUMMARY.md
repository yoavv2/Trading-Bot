# Phase 20.1 Plan 20: T1 per-attempt re-authorization (SAF-02) and dead CAS helper removal (SAF-11) Summary

**Every HTTP attempt (first POST and each in-loop retry) now needs a T1 that re-reads the owner, kill switch, enabled status, window and price age; any "no" pauses the operation through the existing path with zero further POST, and T1 still takes no gate-row lock.**

## Accomplishments

- `operations._require_sendable_gate` (called from `authorize_send` right after the lease check): `load_trading_gate_state` (one plain SELECT, no locking clause) -> ownership block / kill switch / enabled; `permission.evaluation_window_facts` on the operation's evaluation session with `clock.now_utc()`; optional `price_observed_at` age re-measure. Refusals: `NOT_ACTIVE_PAPER_STRATEGY`, `KILL_SWITCH_TRIPPED`, `STRATEGY_DISABLED`, `EXECUTION_WINDOW_CLOSED`, `PRICE_STALE`.
- `submit_orders._SEND_REFUSAL_PAUSE` maps them to `kill_switch_tripped`, `strategy_disabled`, `not_active_paper_strategy`, `execution_window_not_open` (detail = verdict) and `price_unavailable` (detail `price_stale`) through `_move_running`. A retry refusal propagates out of the client's retry loop (it is raised by `begin_attempt`, outside the transport try) to the same handler.
- `permission.price_step` ages the observation from `max(now, fetched_at)` and rejects a future-dated trade; `price_observed_at` flows `_execute_pinned_intent -> _send_authorized -> authorize_send` and `GuardedAttemptLog -> retry authorize_send`.
- SAF-11: `cas_set_intent_disposition` / `cas_update_order` and their exports deleted (no production caller, confirmed by grep before deleting); the CAS test narrowed to `cas_update_operation`.

## Behaviour changes on the send path

- T1 can now refuse with five new reasons; each pauses the operation (existing reasons) and POSTs nothing. Order of T1 checks: operation row lock, state/epoch/executor, DB-clock lease, **owner, kill switch, enabled, window, price**, then intent / order lock / proven-not-sent / G2, then begin-attempt. A gate refusal therefore wins over an intent refusal when both hold.
- `price_step` is stricter: age from `max(now, fetched_at)`; future-dated trade beyond the skew (default 5 s) is `price_invalid`.
- No change to the lock set (operation row, order row), no migration, no new state or reason.

## Residual risk / notes for the orchestrator

- A T1 pause for an elapsed window is `paused/execution_window_not_open` (not `terminated`); termination happens at the next touch (Continue submit/run, End, new session request). Deliberate (see decisions); the operator-visible next action is whatever `effective_state` computes for the lazily-expiring window.
- The legacy summary fields (`blocked_mid_run_global_kill_switch`, `skipped_by_kill_switch`, ownership halt) are populated only by the permission-step pause path; a kill switch or owner change caught by T1 (after the permission check, or on a retry) pauses the operation with the correct reason but does not populate those legacy summary keys. Not asserted anywhere; flag if the console needs them.
- A missing kill-switch / singleton row makes `load_trading_gate_state` raise its typed `ControlStateUnavailableError` inside T1 (fail closed; not a `SendRefusedError`), consistent with the permission step.
- Operator-controls rows are read without a snapshot guarantee relative to the POST: a control change landing after T1 commits but before the request leaves the process is bounded by the 5 s authorization deadline, as before (L5 stays a documented bound, not a closure).
- Doc consumer: `.planning/.../20.1-25` (runbook) should mention that retries re-check the controls (plan 25 is docs-only and already scoped for SAF-02).
