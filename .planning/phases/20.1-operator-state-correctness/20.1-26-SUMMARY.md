# Phase 20.1 Plan 26: CR-01 durable order linkage Summary

**CR-01 closed at the root: `register()` no longer re-parents an existing order, the recovery predicate attributes orders to every Job that originated, registered or retried them through one SQL fragment used by both branches, and each attempt row names the run that sent it.**

## Attribution model (two sentences)

`paper_orders.strategy_run_id` is the ORIGIN run and never changes; a later Continue / retry / Start run is recorded by the accepted `retry_requested` `order_events` row `register()` already writes on that run (the origin's `intent_registered` row likewise). The predicate attributes an order to a flagged Job when it originates on one of its paper_execution runs, an accepted `intent_registered` / `retry_requested` row ties it to one of those runs, or one of its attempts carries the Job as `executor_job_id`; an order can be listed under several flagged Jobs (once per Job) and a sync pass assesses it once.
