# Phase 20.1 Plan 14: Console COMPAT-01 Summary

**The existing console stays truthful while paper-session operation stays API-only: no start or Retry for paper sessions, an Outcome next to every succeeded Job (a paused operation is never plain success), account-scope reconciliation and broker sync, a reconciliation panel that cannot claim "does not block execution" while trading is blocked, and a read-only Active paper strategy line. All backend changes are additive.**

## Accomplishments

- Backend (additive only; tests/test_console_api_contract.py not edited, green):
  - `ConsoleSubmission` StrEnum plus `console_submission_for(spec)`; `paper-session` and `record-external-activity` declare api_only; `job_types.py` emits the field on every item through `getattr`-style helper and still imports no service or ORM module.
  - `JobOutcome` StrEnum (superset of `BatchOutcome`); `outcome`, `outcome_reason`, `outcome_detail` ({failed_count} for partial batches) and `operation` on both `GET /api/v1/jobs` items and `GET /api/v1/jobs/{id}`. Batch values map one-to-one from `derive_job_outcome`; a paper-session Job takes the operation state in its own `result_summary.operation` (so an older paused Job stays paused after a later Continue completes the operation while `operation.state` shows completed).
  - `TradingBlocker` StrEnum and `current_trading_blockers(session, now=None)` in `services/execution/permission.py`, built from predicates shared with `check_intent_permission`; `trading_blocked_reasons` added to the active-paper-strategy view (local import because permission imports operator_controls).
- Console (no page, route, or mutation control added):
  - `paper-session` removed from `JOB_TYPE_FORMS` (form and test deleted); `/jobs/new?type=<api_only>` shows "Operated through the API in this version" with Back to Jobs; picker marks api_only types "API only"; `/paper` shortcut replaced by the notice; Job detail hides Retry for api_only types.
  - Reconciliation and broker-order-sync forms and the two /paper shortcuts submit exactly `{scope: "account"}` (plus `as_of_session` only when entered); `JobShortcutLink` gained `scope` and optional `strategyId`.
  - `outcomeView` in `lib/jobOutcome.ts`; JobsTable and JobHeaderPanel show the lifecycle status with the Outcome ("Succeeded · Paused: working order", ...); only `complete` and no-semantics types get emerald; api_only Job with no outcome shows "Outcome via API only" (neutral).
  - `useActivePaperStrategy`, read-only `ActivePaperStrategyLine` on /controls and /strategy, panel wording: BLOCKS EXECUTION | TRADING BLOCKED: <label> | Trading permission unknown | does not block execution (only for known-empty blockers).
  - `consoleRouteInventory.test.ts` (nine pages) and `consoleMutationInventory.test.ts` (five mutation endpoints, no paper-session literal in sources).
