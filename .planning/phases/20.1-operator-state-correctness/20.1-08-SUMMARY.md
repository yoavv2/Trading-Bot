# Phase 20.1 Plan 08: Owner-less account sync and reconciliation Summary

**Account-level broker sync and reconciliation as `scope: account` on the existing Job types, stored in an owner-less table, report-only, readable through one shared standalone-reconciliation reader.**

## Accomplishments

- Migration 0024 (`down_revision` 0023) adds `account_reconciliation_runs`: no owner column, no FK except `jobs` (`ON DELETE SET NULL`), closed scope and status enforced by the database, `completed_at` index for latest-run reads. Linear chain, single head.
- `reconcile_account`: loads EVERY owner's local orders, fills and open positions, classifies broker activity through the 20.1-07 attribution, compares against the latest broker-observed snapshot (20.1-03 helper), stores findings, divergence, per-symbol unexplained exposure, class/origin-tag counts and unresolved reasons. A page-cap overflow is stored as a blocking `broker_history_exceeds_cap` result and the matcher never runs. It writes no ExecutionEvent, StrategyRun, PaperOrder, Position or correction (source scan pins this).
- `sync_account_state`: applies broker state only to known local orders across all strategies, ingests fills only for them, records one `broker_sync` snapshot with `strategy_id` NULL; never touches positions or orders it does not know.
- `latest_standalone_reconciliation(session, strategy_public_id, scope, completed_after)`: account runs qualify for any strategy-level query; a strategy run is standalone only when it is `trigger_source == 'job'` AND its Job is of type `reconciliation` (in-session runs and runs of other Job types never qualify, R-5). At most two statements regardless of history.
- Both specs accept `scope` (default `strategy`, byte-identical when omitted or explicit). Account scope forbids `strategy_id`, makes `as_of_session` optional, is never ownership-gated (admission takes only the ownership FOR SHARE lock) and declares `broker_effect = reads_broker`.
- Additive reads: catalog `broker_effect`; `GET /api/v1/runs?scope=account` and account run detail; strategy items gain `scope: 'strategy'`; analytics `latest_reconciliation` carries `scope` and consults both tables (+1 statement, test-bounded); job detail lists `account_reconciliation_run` resources and `produced_run_ids` equals their ids.
- Basis traceability (S3-R4): both scopes' sync results carry `snapshot_id` (equal to `account_snapshot_id`) and `applied_orders[{paper_order_id, broker_status, broker_filled_qty, applied_at}]`; a test applies a filled and a canceled order.
