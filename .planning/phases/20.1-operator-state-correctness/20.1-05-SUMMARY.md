# Phase 20.1 Plan 05: Calendar Facts, Execution Eligibility and Calendar State (COR-04) Summary

**Trading day, evaluation session and execution window are three separate closed facts (each with an explicit `unknown(calendar_data_unavailable)`) computed from the persisted calendar; paper sessions are accepted only for the fresh evaluation session inside the `regular_hours_prev_session_v1` window (typed 409 otherwise), calendar sync can run ahead to a configurable horizon, session-scoped defaults come from the evaluation candidate session, and `GET /api/v1/market-data/calendar-state` exposes everything with per-symbol readiness.**

## Accomplishments

- Settings: `market_data.calendar.coverage_horizon_sessions` (>=1, default 60), `runway_low_sessions` (>=1, default 10), `execution.execution_policy` (Literal `regular_hours_prev_session_v1`) and `execution_window_cutoff_minutes` (0..120, default 15), all stated in `config/app.yaml`; out-of-range values are rejected as named `ConfigValidationError` fields.
- `services/calendar.py`: `CalendarOutOfBoundsError`, `previous_session_date`, `next_session_date`, `calendar_horizon_end` (N-th session after today, clipped to the library's last session). Existing functions unchanged. `services/market_data_access.py`: `persisted_session_row`, `persisted_sessions_after`, `bar_counts_through_session` (one GROUP BY statement for any symbol count); existing functions unchanged.
- `services/calendar_facts.py`: closed enums (`FactStatus`, `UnknownReason`, `TradingDayPhase`, `EvaluationStatus`, `EvaluationNotReadyReason`, `WindowStatus`, `WindowClosedReason`, `EligibilityRejection`), frozen result dataclasses with `to_dict()`, `load_calendar_window` (ONE statement), pure `*_from_window` facts, `calendar_facts` bundle, `readiness_from_rows` (pure; calendar_gap > missing_bars > insufficient_history), `session_readiness`, `evaluation_session`, `paper_execution_eligibility` returning `EligibilityResult(rejection, trading_day, evaluation_session, window)`. `now` must be timezone-aware (ValueError otherwise); an unsupported policy name raises `UnsupportedExecutionPolicyError`; everything is read-only.
- Window arithmetic uses the persisted open and close: `until = close - cutoff`, so the early-close day (2025-11-28) closes at 12:45 ET; 15:44:59 is open and 15:45:00 is closed on a normal day.
- `payload_fields`: `require_registered_strategy` returns the strategy, `PayloadFieldRejection.TO_DATE_BEYOND_COVERAGE_HORIZON`, `require_date_range_within_horizon`, `evaluation_session_default` (replaces `latest_completed_session_default`, which is removed; no spec imports it any more).
- `sync-market-sessions`: closed rejection enum swaps `to_date_in_future` for `to_date_beyond_coverage_horizon`; a range wholly after today up to the horizon is accepted and the sync persists it (runway afterwards >= horizon). `ingest-bars` keeps `to_date_in_future` (`test_bar_ingest_into_the_future_is_still_rejected`).
- Defaults: risk-evaluation, paper-session, reconciliation, broker-order-sync return `{"as_of_session": candidate}` and ingest-bars ends its window at the candidate; all return `None` when the calendar does not cover the clock (`test_defaults_are_none_when_calendar_unavailable`). Paper-session defaults never include `risk_run_id`; backtest defaults are untouched.
- `paper-session` `validate_payload`: after the ownership check, eligibility at the injected clock; `PaperSessionSubmitConflict` is exactly the six values; the detail carries `strategy_id`, `as_of_session` and, for `evaluation_data_not_ready`, the closed `reason` and the failing `symbols`.
- `GET /api/v1/market-data/calendar-state[?strategy_id=]`: `as_of` (server time), `policy`, `trading_day`, `calendar_coverage` (last persisted session, runway, `runway_low`), per-strategy `evaluation_sessions` (status, session_date, reason, per-symbol bars/history/metadata) and `execution_windows`. A symbol missing metadata is `metadata: not_ready / missing_metadata` individually while the session `status` stays a bar/history rule. GET only (OpenAPI inventory test), no write (statement spy plus row counts), 4 statements regardless of symbol count (1 when the calendar is unknown).

That is the plan's literal rule; the freshest session becomes executable only on the next trading day D+1 inside its window. 20.1-10/11 and the operator copy should word it accordingly.
- Tests of future plans that submit a paper-session through the real spec must either seed a ready window with an injected clock or use `tests/support/paper_eligibility.allow_paper_execution` when eligibility is not their subject.
