# Phase 20.1 Plan 16: Continue Session, S1 Takeover and the No-Resend Proof Summary

**A paused paper session is resumed only through its own `{mode: 'continue', operation_id}` Job: gated at submit time from persisted evidence, run inside the (strategy, session) advisory lock with an S1 epoch takeover, sending only unsent intents under their original client_order_id and never an in-doubt one, with the two-worker race and every takeover scenario proving one POST per intent.**

## What was built

- **Payload** (`paper_session_submission.py`): mode dispatch before the strict start model. Start (absent or `"start"`) is unchanged and never carries `mode` in its normalized form (golden dict test). Continue is hand-parsed to exactly `{mode, operation_id}` and normalizes to `{mode: 'continue', operation_id: <canonical uuid>}`. New closed rejections: `invalid_mode`, `operation_id_required`, `invalid_operation_id`, `operation_id_forbidden_in_start_mode`, `continue_forbids_start_fields`, `operation_not_found` (422). `PaperSessionSubmitConflict` gains `operation_not_paused` and `awaiting_reconciliation` (`working_order_commitments_unaccounted` is shared with start mode); three exact-set pins moved in lockstep.
- **Submit gate** (`continue_precheck`): ownership -> recovery gate -> effective state (`will_end` accepts; not paused and not `takeover_pending` -> `operation_not_paused` with the state) -> `strategy_working_orders` -> `awaiting_reconciliation` (`latest_broker_effect_at` + `latest_standalone_reconciliation`, the same predicate the permission check uses). Read-only.
- **Run time** (`run_paper_continuation`): as above; the continuation intent resolver can bind only `reuse_existing | retry_existing | create_new`, anything else raises `ContinuationIdentityChangedError` with nothing registered or sent. An empty continuation completes the operation only when `settled_blocker` finds no unresolved outcome, no working or unsynced order and a clean reconciliation after the latest effect; otherwise it pauses with that reason. The function names none of `apply_reconciliation_corrections`, `recover_inflight_paper_orders`, `reconcile_paper_execution`, `load_broker_state` (AST test).
- **Operations**: `OperationExecutorActiveError`, `adopt_running_operation` (crash-left `running` operation; refuses while another Job is live), and an `exclude_job_id` parameter through `live_job_ids`, `effective_state` and `touch_operation` so the Continue Job does not count itself as live.
- **Handler**: continue mode reads no strategy or session from its payload (they come back on the report); the additive `operation` object is kept.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Flagged-Job attribution in the recovery predicate (found by scenario v2)**
- **Found during:** Task 2, v2 (pre_connection after takeover, then a proven-not-sent send by a new executor)
- **Issue:** a retry re-parents `PaperOrder.strategy_run_id` to the new run. The reclaimed (`outcome_uncertain`) Job of the first executor was then left with a paper_execution run and ZERO order rows, which the E-5 rule reads as `execution_path_unproven`: the strategy blocked forever and the intent that recovery had established `not_sent` could never be sent. The safe failure mode (no resend) held, but the documented liveness (a proven-not-sent send by a new executor) was broken.

### Interpretations (reported)

- **Epoch numbering.** The start executor holds the creation epoch 0, so takeover B is epoch 1 and worker C epoch 2 (the plan's text counts 1 -> 2 -> 3). Tests assert the relative steps (A, A+1, A+2).
- **S-b premise.** An executor that records an ambiguous outcome and then pauses normally leaves the operation `paused`, where `acquire_execution` (which needs `running`) does not apply. S-b therefore models A dying right after it recorded the outcome and before the pause (the pause write raises, `_best_effort_pause` is a no-op); the Job is then reclaimed. `probe_send` runs the real T1 against the operation forced `running` at the probing fence (restored afterwards), because a paused operation would refuse for `operation_not_running` before the per-intent rule is reached.
- **Test fixtures run a linked Job.** The S1 scenarios give worker A a real Job row and link its run to it, so the recovery predicate sees the Job (and its uncertain flag after the reclaim).
- **`get_job_recovery` and `_block_from_conflict` for continue Jobs.** A continue payload carries no `strategy_id`, so the Job-detail recovery view reads account-level (the stricter view) and a retry block carries `strategy_id` None. No call site was changed.
- **`ruff format`.** The pre-commit formatter reformatted `submit_orders.py` and `tests/test_paper_session_operations.py` as a whole, so those diffs include formatting of untouched lines.
- Continue-path tests named in the plan that already existed from 20.1-15 (earlier fill, cash shortfall, price pause then same intent, kill-switch reset) were kept under their names and now run through the product entrypoint (the `continue_operation` helper delegates to `run_paper_continuation`); new Continue-mode variants were added for manifest change and risk-limit failure.
