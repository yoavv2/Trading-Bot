## Accomplishments

### The three E1 windows, now regressions on the product path
Each one runs the real `reconcile_paper_execution` against a scripted broker that shows an unrecognized order, so the new run is dirty. The attacker uses its own connection.
- **(a) Pre-run window:** a hook on the first broker read proves no run row exists yet, then retypes the Job.
- **(b) Insert race:** an `after_flush` listener fires while the run INSERT is sent but not committed. The second transaction is proven not to see the run, and the listener is always removed.
- **(c) Shadow:** a TEMP `strategy_runs` table, under three caller search paths, with the shadow proven active.

Every case is refused with SQLSTATE 23000 and the 0030 message, never 55P03. Afterwards:
- the Job is still `reconciliation`;
- the dirty run is the newest standalone strategy reconciliation;
- the gate is `reconciliation_not_clean`.

Against the unamended 0030, every attack was accepted, the Job became `backtest` and the gate released (`None`).

### Lookup hardening, pinned at trigger level
- **Shadows (28 nodes):** guard 4's retained EXISTS arm, guard 1's three EXISTS arms, and the 0029 delete guard's R and J arms ignore TEMP and caller-owned-schema shadows under four caller paths.
- **Planted operators (7 nodes):** an operator planted in `public` cannot change any 0030 verdict.
- **Origin guard (1 node):** the 0029 origin guard (CR-01 durable linkage) resists a reordered caller path plus a planted `=(uuid, uuid)`.
- **Pre-planted operator (1 node):** an operator planted before the migration runs cannot capture guard 4's WHEN, and no 0030 trigger depends on a non-pg_catalog operator.

### Approved scope widening, with legitimate writes preserved
- Queued, running, completed and account-scope reconciliation Jobs keep their type, and no Job becomes one.
- Every lifecycle write still works: claim, lease renewal, progress, success, failure, queued cancellation, and running cancellation with acknowledgement.
- A same-value write passes.
- A real account reconciliation completes.
- Unrelated retypes stay legal.

### Configuration pins
- `proconfig = {search_path=pg_catalog, public, pg_temp}` on the four 0030 functions and the two 0029 guards.
- No function is SECURITY DEFINER.
- The untouched functions (two 0029 functions, 0028, 0025, 0026) keep `proconfig` NULL.
- Every table reference is `public.`-qualified.
- The `'reconciliation'` and `'job'` literals are pinned against `RECONCILIATION_JOB_TYPE` and `STANDALONE_TRIGGER_SOURCE`.

### Intermittent test
`test_a_service_that_never_touches_the_attempt_log_still_leaves_a_complete_attempt` has failure-only, read-only diagnostics; its assertion is unchanged. On failure the message reports:
- the operation state, reason and detail, and the returned report;

- the intent, order, attempt, Job, execution-event, singleton, kill-switch and strategy rows;
- wall-clock versus monotonic elapsed time, plus DB and Python clocks;
- a verdict: stopped before sending, or attempt recording failed.

### Intermittent test (open, cause not established)
- It passed in the full suite and in 10 further runs, so nothing was captured.
- Code reading, confirmed by the re-verifier with two refinements:
  - An order registered with zero attempt rows and a normal return means T1 (`authorize_send`) never committed an attempt row.
  - So nothing was sent. Execution legitimately stopped before sending, by a T1 refusal mapped to a pause or by `outcome_unresolved` / `intent_not_sendable`.
  - A failure while recording the attempt would re-raise, and the test would error rather than fail an assertion.
- A scratch run that forced a T1 `price_stale` refusal reproduced the observed shape exactly:
  - one `pending_submission` order and 0 attempts;
  - the service never called and the report returned;
  - the operation paused `price_unavailable` / `price_stale`.
- Time-dependent candidates under the test's seams:
  - `price_stale`: a wall-clock jump of more than 120 s forward, or more than 5 s back, between the price fetch and T1;
  - `intent_not_sendable`: a database clock step back between operation creation and registration.
- The diagnostics now discriminate between them.
