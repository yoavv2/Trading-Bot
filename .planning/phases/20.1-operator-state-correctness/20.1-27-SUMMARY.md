## Delete predicates as implemented

- O paper_orders, E order_events, X (execution_operations, execution_operation_intents, execution_operation_jobs, paper_fills), A account_reconciliation_runs: every row.
- R strategy_runs: `run_type IN ('paper_execution','reconciliation')` OR referenced by paper_orders / order_events / order_submission_attempts.
- J jobs: `job_type IN ('paper-session','broker-order-sync')` OR `outcome_uncertain` OR referenced by a strategy_runs row with run_type 'reconciliation' (W-N2).
- order_submission_attempts, recovery_records, external_broker_activity: no new DELETE trigger (0028 / 0026 / 0025 already reject DELETE); TRUNCATE guards only.

FK/cascade map as implemented: no FK was rebuilt. A parent delete (strategies, symbols, strategy_runs, jobs) that cascades into a protected row fires that child's BEFORE DELETE trigger, which raises and aborts the whole statement (nothing removed, asserted by row counts). The 0028 `SET NULL` shape B on attempts.strategy_run_id stays legal in the 0028 trigger but is unreachable for any run an attempt references (that run is undeletable).

## Retention-policy note

This plan changes retention: evidence rows are no longer deletable by any writer (code, operator, DB client), directly or by parent cascade, and evidence tables cannot be truncated. No product delete path existed (grep of src/, alembic/, scripts/ found none; `tests/test_recovery_predicate.py` pins recovery.py has no recovery_records delete), so only DB-level operator actions and the flipped tests were affected. Downgrade scripts below 0029 (0004/0007/0008/0010/0012) run after 0029's downgrade has dropped its triggers. Whole-database drops in test fixtures are unaffected.

## Deviations from Plan

None to the plan's scope. Notes:

- [Test construction] The W3 "refused order-less run delete" test compares the verdict fields (`resolved`, `gate_code`, `intents`) of `get_job_recovery` plus the strategy gate, not the whole dict, because the evidence package carries evaluation-time stamps that differ between calls. The assertion that matters (unresolved / execution_path_unproven identical before and after) is unchanged.
- [Test construction] Plain `TRUNCATE` of a table referenced by an FK is refused by PostgreSQL itself (SQLSTATE 0A000) before any trigger; those tables are tested with `TRUNCATE ... CASCADE` (which reaches the trigger), unreferenced tables with both forms. The message is asserted to name the table so the table's own guard is proven.
- Symbol-delete cascade test asserts IntegrityError + unchanged counts without pinning SQLSTATE (the guard on paper_orders and an FK RESTRICT from risk_events can race by trigger order; either way nothing is removed).
