# Phase 20.1 Plan 23: Execution sizes only against a fresh broker-observed basis (SAF-09) Summary

**No order can now be sized or sent on the configured-cash fallback or on a broker snapshot older than `execution.account_snapshot_max_age_seconds`: the per-intent permission check pauses `awaiting_reconciliation` and basis verification refuses with `evaluation_basis_unverified`; snapshots are stamped after the account read with the application clock.**

2. Task 2 (E2E harness M4 in `own()`): `3341c4d`

## Behaviour changes

- `check_intent_permission` step (5): `load_state_with_basis(..., now=at)`; `execution_basis_problem` non-None -> `PAUSE`, reason `awaiting_reconciliation`, step `risk`, detail `account_snapshot_missing` (basis source not `broker_sync`) or `account_snapshot_stale` (age > max; age == max proceeds). No revalidation, no POST. Operator remedy unchanged: M4 -> M5 -> M11.
- `verify_evaluation_basis`: `configured_starting_cash` -> `basis_not_broker_observed`; `broker_sync` with recorded age missing or > max -> `basis_stale`; both ahead of `predates_executions`, for empty history too. A risk run that recorded no basis is judged by the old rules.
- `sync_paper_state` / `sync_account_state`: `snapshot_at` = `clock.now_utc()` read right after `get_account()`; `PortfolioService.load_state_with_basis` default `now` is `clock.now_utc()`.
- Tests proving it: `tests/test_account_basis_freshness.py` (12 tests including the eight named ones; the stamping and overlap tests were verified to fail when `snapshot_at=synced_at` is restored).
