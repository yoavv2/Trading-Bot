# Phase 20.1 Plan 01: Single Active Paper Strategy Summary

**PAPER-01: a DB-enforced single-row ownership singleton (seeded with no owner) gated at submit, at Job admission under a FOR SHARE singleton lock, and at run time before every broker action, with a one-statement shared gate loader (R-Q1) and new strategies created disabled.**

## Accomplishments

- Migration `0022_phase20_1_active_paper_strategy` creates `active_paper_strategy` (PK `id` smallint, CHECK `ck_active_paper_strategy_singleton` `id = 1`, strategy FK RESTRICT, `set_by_run_id` FK SET NULL) and seeds `id = 1, strategy_id = NULL`. A second row, a duplicate id and `UPDATE id` are each rejected by PostgreSQL (tested). Single alembic head.
- `load_trading_gate_state(session, strategy_id=None)` (R-Q1) reads kill switch, owner and owner status in ONE statement; `load_kill_switch_state`, `load_strategy_control_state` and `ownership_block_for` are thin wrappers; `run_paper_session`, the guarded body and every per-candidate re-read use it. Identity and 1-statement tests included.
- `JobSubmissionConflictError` -> HTTP 409 `{code, job_type, strategy_id}` on submit and retry. `PaperSessionSubmitConflict` / `ReconciliationSubmitConflict` are closed enums (exactly the two ownership codes). broker-order-sync, backtest, risk-evaluation, ingest-bars and sync-* are not gated.
- SER: admission of paper-session, reconciliation and broker-order-sync takes the singleton `FOR SHARE` inside the Job-insert transaction (submit and retry), re-runs `ownership_block_for` with the transaction's own session, and fails closed if the row is missing. Race tests (handover in flight blocks admission, then admission refuses; submit committed first is visible to the handover's A1 query; broker-order-sync also serializes) pass.
- Run time: ownership read before `load_broker_state` (zero broker calls on a handover between submit and claim, asserted with recording fake broker client and execution service, and at Job level); guarded body blocks with `blocked_not_active_paper_strategy`; per-candidate re-read halts remaining candidates with `blocked_mid_run_not_active_paper_strategy` and leaves the already-submitted order untouched.
- R-8: `ensure_strategy_record(..., initial_status=DISABLED)` (existing rows untouched); the pure control read reports `disabled` for a strategy with no row.
- Read-only `GET /api/v1/controls/active-paper-strategy` (typed 503 `control_state_unavailable` when the row is missing; no write). `run_paper_session` requires an explicit `strategy_id`; no paper-path module mentions `default_strategy_id` (source-scan test).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `alembic_version.version_num` is VARCHAR(32)**
- **Found during:** Task 1
- **Issue:** the mandated revision id `0022_phase20_1_active_paper_strategy` is 36 characters; Alembic's `UPDATE alembic_version` failed with `StringDataRightTruncation`.
- **Fix:** `upgrade()` first widens the column to VARCHAR(255). `downgrade()` deliberately does not narrow it (the row still holds the long id at that point, narrowing would fail); the wider column is harmless. This also unblocks the long ids of 0023-0027.
- **Files modified:** `alembic/versions/0022_phase20_1_active_paper_strategy.py`
- **Commit:** `2c0bdd6`

**2. [Rule 1 - Bug] `JobSubmissionConflictError` cannot be a frozen dataclass**
- **Found during:** Task 3 (retry route test)
- **Issue:** the admission re-check raises inside `session_scope` (a contextmanager); `contextlib` re-assigns `__traceback__`, which a frozen dataclass forbids (`FrozenInstanceError` -> HTTP 500).
- **Fix:** plain `ValueError` subclass with `job_type`, `code`, `detail` (defaults to an empty mapping). Covered by the retry test and the admission race tests.
- **Commit:** `96d6757`

**3. [Rule 2 - Missing critical functionality] R-Q1 loader and SER admission had no task action**
- **Found during:** orientation (must_haves truths 1 and 4)
- **Fix:** implemented both. Because `tests/test_orchestration_boundaries.py` forbids `orchestration/job_mutations.py` from importing `trading_platform.services`, SER is a spec attribute `check_admission(payload, *, session)` resolved by `jobs.registry.admission_check_for` (same pattern as `retry_prerequisite_for`); `job_mutations.py` calls it inside the Job-insert `session_scope` before `submit_job` in both `submit` and `retry`.
- **Commits:** `de1d341`, `96d6757`

### Plan adjustments (no behaviour change to the spec)

- The gate loader is in `services/operator_controls.py` rather than `services/active_paper_strategy.py` (import-cycle avoidance, see key-decisions). `ownership_block_for` (acceptance greps, key_links) exists in `active_paper_strategy.py` as the session-accepting wrapper and as `TradingGateState.ownership_block_for` for the engine.
- Handover/PUT is 20.1-12, so the SER race tests simulate the handover with a second connection holding `FOR UPDATE` on the singleton and writing the owner; the A1 side is a direct query. Real PUT-vs-submit racing belongs to 20.1-12.
- The 0021 refused-downgrade test now compares `alembic_version` to the script-directory head. `alembic/env.py` has no `transaction_per_migration`, so the whole downgrade runs in one transaction and a refusal by 0021 also rolls back 0022's downgrade (verified: version stays at head).
- `tests/test_operator_controls.py::test_config_disabled_strategy_with_no_db_row_has_one_default_status_everywhere` lost its analytics leg (moves to 20.1-03 / 20.1-13), as the plan states. Other changed assertions are annotated R-8 or arrange the strategy explicitly (`seed_registered_strategy`).
- `tests/test_paper_execution.py::_seed_approved_risk_batch` (and the equivalents in `test_alpaca_execution.py`, `test_concurrency_guard_e2e.py`, `test_paper_session_job_e2e.py`) now create the strategy enabled AND make it the owner by an explicit direct write (`owner=True` default, `owner=False` for non-owner cases). `strategy_jobs_env` in `test_strategy_job_types_e2e.py` does the same.
- Two spec tests that previously ran without a database (`validate_payload_normalizes*`) now use a migrated DB because the ownership check reads it.
