## The appended note (runbook 05, after the CR-01 interim amendment)

> **Note (2026-10-05, CR-01 fix in plans 20.1-26..30 - PENDING VERIFICATION; the interim prohibition above remains in force and is not lifted by this note):** this note only records what the code now does; it changes no instruction. (1) An order keeps the run that first registered it; from migration 0029 (20.1-27) the database refuses any change of that origin run. (2) Every later Continue (M11), Retry (M15) or new start (M10) that re-registers the same order is recorded in the order's history, and R3, the strategy gate, A5 and the operation read (R2, which lists unresolved intents by the same verdict as the gate) use that history: an order is attributed to every uncertain Job that originated, registered or retried it, so the original uncertain Job is no longer left with no orders. (3) A Job that crashes after re-registering an order is attributed the same way and does not become `execution_path_unproven`. (4) Unchanged: a genuinely ambiguous attempt (no outcome, a timeout or an error after the connection was made) stays `outcome_unresolved` before and after reconciliation and End; legacy orders without an attempt log (TL-4) stay blocked; a Job that created a run but registered no order stays blocked as `execution_path_unproven` today, because the absence of an order is not proof that nothing was sent, and whether positive evidence could release it is an OPEN decision (OD-1), not an approved terminal state; R3 is read-only evidence; End + M5 is not a release; no database edit, override or resubmission is ever part of a procedure. Known open display difference (not fixed): an UNKNOWN order whose complete attempt history shows it never left the process (`pre_connection`) is treated by the gate and A5 as proven not sent (`reconciliation_required`, A5 passes after a fresh clean M5) while the operation read still displays that intent as `ambiguous` and its `unresolved_intents` does not list it; nothing is ever sent for it. Run-level reads of the legacy console still attribute a continued order to its origin run. (4b) From migration 0029 evidence rows cannot be deleted or truncated, directly or through a parent record: orders, order history (also append-only), execution operations and their intent and Job links, fills, paper_execution and reconciliation runs, paper-session and broker-order-sync Jobs (and any Job flagged uncertain), and the account reconciliation runs; the attempt log, recovery records and external broker activity cannot be truncated (their rows were already undeletable). This is a retention policy (user decision 2026-10-05); account snapshots are not covered. (5) Where CR-01 already happened before the fix, the recorded registration history attributes the order back to the original Job after the upgrade (20.1-27 test); this is also pending verification, and until verification the step-5 "If CR-01 has already happened" instruction applies unchanged. (6) Lifting the prohibition requires the verification of these plans and an explicit user decision.

- WR-04 (OPEN): `verify_evaluation_basis` fails open for a missing or unknown basis source. Reason deferred: intent_identity basis rules, not a CR-01 consumer; the per-intent permission check still refuses a stale or non-broker basis before every POST.
- WR-05 (OPEN): `load_basis_verification_rows` reads the cached global settings, not the caller's. Reason deferred: settings threading, no shared code with CR-01.
- WR-06 (OPEN): a future-dated account snapshot always reads fresh and outranks later ones. Reason deferred: portfolio snapshot freshness; needs clock skew between hosts.
- WR-08, T1 half (OPEN): `authorize_send` refuses a REJECTED history as INTENT_NOT_SENDABLE and pauses outcome_unresolved. Reason deferred: unreachable through the loop after 20.1-28 (the register guard applies the rejection first); remapping it needs a pause reason outside the closed D-18 set.
- WR-08, guard half only PARTLY closed (OPEN, finding from execution, 20.1-28): the guard in `register()` applies a recorded rejection only for a PLANNED intent that resolves to an older retryable order. The REVIEW-described shape (an intent already bound to its order whose history is rejected, ambiguous or unfinished) is skipped by Continue's `_load_open_intents` (it filters on `derive_intent_state`): it is never resent but also never applied as rejected, so the operation can complete while the order stays `pending_submission` / `submission_failed` with a rejected history (the gate treats it as established; nothing is sent).
- S14 display / gate mismatch (OPEN, finding from execution, 20.1-28 deviation 4 and 20.1-30 pin): an UNKNOWN order with a complete `pre_connection` history is PROVEN_NOT_SENT. The gate and A5 release it after a fresh clean reconciliation (`reconciliation_required`, then None), while the operation read model still displays the intent `ambiguous`, the operation still reads `paused / outcome_unresolved`, and `unresolved_intents` / End do not list it (End cancels only the later intent). The order is never POSTed. Decision needed: list it with a reconciliation-type blocking effect, or have recovery reclassify it.
- Account snapshot deletion (OPEN, user decision; raised by the plan checker 2026-10-05 under W4): `account_snapshots` are NOT protected by 0029 (unguarded). Deleting a newer account snapshot can make an older snapshot that is still within `execution.account_snapshot_max_age_seconds` the sizing basis (`account_baseline` selects the latest by `snapshot_at`). No product delete path exists. Whether to guard them is left to the user.
- OD-1 (OPEN user decision): whether durable positive evidence plus revoked executor authority may release an order-less flagged paper-session Job (investigation in 20.1-30, pending proposal `20.1-OD-1-DRAFT.md`, not executed; it carries the user's 2026-10-05 direction: End or persisted expiry may only CONTRIBUTE proof of revoked authority, release needs the complete protected evidence chain, pre-0029 Jobs do not qualify automatically, TL-4(a) and ambiguous or unfinished attempts stay blocked).
